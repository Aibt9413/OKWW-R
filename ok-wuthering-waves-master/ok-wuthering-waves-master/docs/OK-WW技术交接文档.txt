四、OKCombo v2.1 语法（核心，务必保持与实现一致）
--------------------------------------------------------------------------------
规则（逐字符解析，大小写不敏感；空格/逗号为可选分隔符）：
  1. 裸数字 1/2/3（动作字母前） = 切换角色位
  2. 动作字母：A=普通攻击(鼠标左键点按)  H=重击(左键长按)  E=共鸣技能  Q=声骸技能
     R=解放技能  T=工具键  J=跳跃  F=处决
     （键盘动作全部动态读 task.key_config，不硬编码；处决键回退 'f'）
  3. 重复次数 = 字母后括号/乘号：A(3) 或 A×3 = 普攻3次（必须括号，裸数字不表示重复）
  4. 重击长按 = H 后裸数字：H800 = 长按800ms；H 无数字 = 该出招表的
     heavy_hold_ms 配置（默认 1000ms）
  5. 延迟 = D<毫秒>（如 D500）或 delay(500)；D 后接数字建议用空格分隔避免粘连
  6. 歧义规则：动作字母后紧跟裸数字会报错（提示用空格分隔或括号），
     切角色位数字必须与前一动作用空格/逗号分隔（如 2E 3Q）
示例：
  1A(3)H800 2E D300 3Q
    = 切位1 → 普攻3次 → 重击长按800ms → 切位2共鸣 → 延迟300ms → 切位3声骸
存储格式（JSON sequence 数组）：
  ["slot(1)","attack(3)","heavy(800)","slot(2)","resonance","delay(300)","slot(3)","echo"]
往返函数：parse_sequence_text(文本→列表) / sequence_to_text(列表→文本，自动补空格保无歧义)

五、执行机制（combo_executor.py）
--------------------------------------------------------------------------------
1. 触发：全局热键 → combo_executor.trigger(combo)（独立线程执行，防重入）
2. 流程：暂停当前任务（executor.pause(current_task)，仅暂停单个任务非整个工具）
   → 鼠标中键点按 mb_click_count 次（默认2，解除锁定）→ 执行序列 → 恢复任务
3. 指令间隔：每条指令后自动等待 default_interval_ms（默认120ms，可配）；
   delay(N) 用显式 N 毫秒替代该处间隔
4. 角色切换：目标位 = 当前位循环下一个(1→2,2→3,3→1) 时调用项目
   task.switch_next_char()（智能切换，带入场/协奏逻辑）；跨度>1 时直接发数字键 1/2/3
5. 绑定匹配：bind_role（角色类名在 task.chars 中）/ bind_team（角色名集合）/ bind_slot
   （角色位）任一不匹配则 InfoBar 提示并跳过
6. 触发次数：trigger_count>0 时达上限后忽略触发并提示（内存计数）

六、全局热键（hotkey_manager.py）
--------------------------------------------------------------------------------
1. Win32 RegisterHotKey(None, id, mod, vk)，id 从 1000 起分配（避开 StartCard=999、
   DebugTab=1,2）；Qt 侧通过 QApplication.installNativeEventFilter 捕获 WM_HOTKEY(0x0312)
2. 结构要点：QAbstractNativeEventFilter 不是 QObject，信号用独立 _HotkeySignals(QObject)
   组合承载（多继承会导致信号源被 GC 销毁——已踩坑）
3. 冲突检测（保存时红字阻止）：
   - 游戏键位：快捷键主键 ∈ key_config 全部值 ∪ {lmb, mouseleft}
   - 其他出招宏重复（normalize_hotkey 比较）
   - 系统占用：RegisterHotKey 试注册失败即被占用（Win+D 等系统热键注册必失败）
4. hotkey 字符串格式："Ctrl+1" / "Alt+X" / "F12" / "Win+Shift+S"（normalize 统一首字母大写）

七、custom_combos.json 字段 schema
--------------------------------------------------------------------------------
{
  "combos": [{
    "id": "毫秒时间戳",
    "combo_name": "名称",
    "bind_role": "Jinhsi" | null,       // 角色类名（53 个角色 src/char/*.py）
    "bind_team": ["Jinhsi","Verina",...] | null,   // 角色名集合（可自定义输入）
    "bind_slot": 1|2|3 | null,          // 角色位
    "sequence": ["resonance","delay(200)",...],
    "hotkey": "Ctrl+1",
    "trigger_count": 0,                  // 0=不限
    "mb_click_count": 2,                 // 执行前中键次数
    "default_interval_ms": 120,          // 指令默认间隔
    "heavy_hold_ms": 1000,               // 重击默认长按毫秒
    "description": "招数描述",
    "key_mapping": {...},                // 分享时附带（发送方键位映射）
    "enabled": true,
    "created": "...", "updated": "..."
  }]
}

十、重要坑点备忘（务必先读）
--------------------------------------------------------------------------------
1. CustomTab.executor 会被 MainWindow 赋值为 TaskExecutor（MainWindow 注册
   custom_tabs 时 tab_obj.executor = executor）——宏执行器必须用独立属性
   （ComboPanelTab 用 self.combo_runner），否则热键回调 AttributeError
2. 配置文件（configs/*.json）修改必须无 BOM UTF-8 写入，否则 ok 的 JSON 解析
   失败触发 reset_to_default 回写默认值（Auto Start 配置曾因此被回写）
3. qfluentwidgets 的 setStyleSheet 通道会被 StyleSheetManager/DirtyStyleSheetWatcher
   管理，自定义 QSS 用 setCustomStyleSheet；setProperty 后需重应用样式表
4. 序列列表→文本往返必须保证无歧义（slot 前补空格），否则保存后预览失效
   （已修复，勿回归）
5. 热键 id 避让：999（StartCard）、1/2（DebugTab）；热键管理器从 1000 起
6. pyappify 非打包环境 get_version_list 报错为无害（日志噪声）
7. 自动启动游戏开关：configs/Basic Options.json 的 "Auto Start Game When App Starts"
   （当前为 false；true 时 ok-ww 启动即拉起游戏）
8. 离屏渲染（QT_QPA_PLATFORM=offscreen）下字体目录缺失为正常现象，不影响验证
